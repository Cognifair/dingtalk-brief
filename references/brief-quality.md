# 可追溯简报的质量规则

## 事实与行动

- 把「明天 / 周一 / 今晚」等相对日期按**消息发送时区**解析，不按生成简报的今天解析；日期字段不必然是截止时间。
- 新通知更正旧安排时，以明确的更正为当前依据，简要说明变更并保留两条来源。不明确的冲突标为待确认。
- 已经过期的安排归为历史 / 需核实，不直接列为未来待办。没有完成状态证据时，不说用户尚未完成；**发送者也不自动等于负责人**。
- 任务候选保留行动、对象 / 条件、明确截止时间或「待确认」、优先级依据及原文证据。默认只列候选，不创建任何任务。
- 人名、分组、提交地址、数量和截止日期若只依赖不清晰 OCR，标低置信度。证据不足时不补全，不把推断写成老师原话。

## 来源与交付

- 每个关键结论尽量带 `群名 · 发送者 · 本地时间 · message_id`，以及短原文或媒体编号。有真实可用深链才给消息链接；**不要编造钉钉跳转链接**。
- 通常采用这些信息块，按实际内容简化，无内容不硬凑：

1. 范围与覆盖：账号的非敏感标签、群、明确起止时区、缓存快照时间、各群唯一消息数、是否完整分页。
2. 四象限重点：按 SKILL.md「摘要结构（四象限）」的四个固定标题组织，每象限写事项、截止 / 状态、来源和待确认点；空象限写「无」。
3. 图片 / 文件增量：哪些信息来自媒体，哪些已视觉核对。
4. 未覆盖与风险：缺失、低清、失败、未返回的媒体数量，以及缓存不等于完整历史。

- 已过期或截止时间已过的安排单列「已过期 / 需核实」，不塞进四象限；象限分类只写原文能支撑的紧急度和重要性依据。
- 在聊天内交付或保存 Markdown；附件清单较长时独立保存。不要在交付文件里暴露本机账号缓存标识、凭据或临时签名链接。追溯路径可放在任务私有清单里。

## 与其它能力的边界

本技能只负责「读消息 → 出简报 → 可选推送」。写入待办清单、发群消息、管理群成员属于其它技能或产品的能力；用户要走出这一步时，换用对应能力并重新核对授权。
