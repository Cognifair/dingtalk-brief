# 图片、文件与云端解析

## 建立媒体清单

仅从已选群、已定时间窗内的消息提取媒体引用。每个引用保留 `cid/message_id/source_time`，关联实际本地文件后记录类型、字节数、SHA-256、尺寸或页数、来源路径及状态。内容哈希去重上传，但保留同一文件在不同消息中的所有引用。

区分原图、清晰缓存、低清预览、缺失附件和富文本内嵌图片。不以文件名相同认定内容相同，不扫描整个用户下载目录补抓。对已知缓存格式，只能用精确消息键/内容标识进行限定目录匹配。

极小图（例如最长边不足256像素）可先标为低清，避免消耗云端额度；此阈值只是筛选启发，不代表其他图必然清晰。文件扩展名应与真实格式一致；不执行宏或附件程序。多帧图/多页文件不能默认只读首帧/首页。

## 自动下载原图：有条件尝试，不是已实现接口

本地导出器只能读取已有缓存，不能据此宣称会下载远端原图。

用户要求补下载时，使用环境中可用的 `computer-use:computer-use` 技能，并先完整阅读其说明。只操作真实发现的钉钉窗口：在指定群定位源消息，使用客户端提供的“查看原图/下载/另存为”，下载后核对文件与消息。登录、验证码交给用户。不抽取 Cookie/Token、不注入客户端内部 API、不绕过下载限制或到期权限。

操作可能影响已读/访问记录，应事先说明。不保证管理员不可见。没有可操作窗口、原图已过期或下载被禁止时，报告具体缺口；不要把缩略图放大后称为原图。当前环境未完成真实原图自动下载验证。

## 云端 OCR

用户选择云端后，优先使用本环境可用的 `memo-mineruocr`（Memo-MinerUOCR）技能，完整读取其 SKILL.md 及该技能要求的云端参考，再按其官方接口和脚本执行。缺少该技能时说明依赖，不悄悄换服务商或匿名接口。云端上传授权应涵盖实际文件，不能从“能否做到”推断批量上传许可。

提交前展示或概述服务商、文件数量、总大小及群/时间范围；检查授权仍匹配当前清单。只检查凭据是否配置，不展示凭据内容、长度或片段，不把 Token 写入参数、技能文件、报告或日志。

需要保留的操作约束：

- Token 只用于官方 API 的 Authorization，不发往对象存储上传地址或结果下载地址；签名 URL 不写入交付文档。
- 使用当前官方格式/大小/页数限制。2026-10-19 已验证精确 v4 API 支持图片、PDF、Word/PPT/Excel；单文件上限200MB/200页，上传批次按文档较窄限制50文件处理。执行前重新核对；不把额度描述为永久免费/无限。Office 转换前页数未知，CSV 不能改扩展名冒充支持格式。
- 在上传前持久化 batch ID、data_id、源哈希和范围。已提交/完成记录不再提交；状态不明先查询而不是重传。身份、配额或限流失败停止并说明，禁止无限重试。
- 校验 HTTPS 域名及跳转；安全解包结果，拒绝路径穿越、符号链接、重复成员及压缩炸弹。保留结果哈希，验证 Markdown 的本地图片引用。
- 查询采用有界轮次；后续只查询/收集已知任务，不隐式提交剩余文件。要定时追踪需用户另行要求并使用产品机制。

接口返回完成只表示结果交付，不保证识别正确。检查表格是否错列、姓名/数字是否幻觉；会影响截止时间、报名资格或分组的内容需要视觉核对，不能用语义猜测填空。

## 覆盖账本

分开统计“媒体引用数”“哈希去重后的文件数”和“已解析文件数”，避免把去重当漏读或把全部结果返回当全媒体覆盖。状态建议：已解析、低清待补、未缓存、原图不可用、不支持、解析失败、已提交待取回、状态未知待核查。

每个缺口注明源消息、原因及用户可采取的补齐方式。文件消息气泡或图片里的文件名不等于取得文件正文。无法获取时，只摘要可见说明，明确文件内容未读。
